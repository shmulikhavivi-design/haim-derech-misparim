**מה צריך לבדוק או לשנות:**
- **הקישור העצמי דורש `confirmation_sent_at`.** אם אישור האימייל כבוי בהגדרות Auth, אף אחד לא יוכל לקשר את עצמו. צריך לבדוק בשלב 0.

- **הספירות ב-`hdm_my_data` מבוססות על שדות בנתונים.** הן יהיו אמינות רק אחרי נעילת `docs`.
- **חלק הממשק ב-`index.html`** ייכתב מחדש על בסיס הקוד הנוכחי, ולא ימוזג.

**ההמלצה:** לא למזג את PR #5. נעביר ממנו את טבלאות הבעלות לשלב 1, אחרי בדיקה מלאה ב-Staging. את מסך "המידע שלי" נוסיף בסוף. אחרי שהכול יעבור, נסגור את PR #5 בלי מיזוג.

## 3. ארכיטקטורת היעד

**זהות:**
- Supabase Auth הוא מקור האמת.
- כל בקשה של האפליקציה נשלחת עם זהות המשתמש (JWT).
- בשרת, `hdm_current_profile()` מחזירה את הפרופיל של המשתמש המחובר מתוך `hdm_profile_owners`, ולא מתוך מה שהדפדפן שולח.

**`docs` עם RLS לכל אוסף:**

| אוסף | קריאה | כתיבה |
|------|-------|-------|
| `profiles` | רק השורה שלי. אחרים: דרך פונקציה שמחזירה שדות ציבוריים בלבד | רק השורה שלי (הגבלת הגיל נשארת) |
| `interests` | רק מה ששלחתי | רק דרך `hdm_send_interest` |
| `matches` | רק אם אני משתתף | רק דרך `hdm_open_chat` |
| `chats` | רק אם אני משתתף (העדכונים החיים ממשיכים לעבוד) | רק דרך `hdm_send_message`. השולח נקבע בשרת |
| `chatReads` | רק שלי | רק שלי |
| `blocks` | חסימות שלי, וחסימות עליי (מזהים בלבד, כדי שההסתרה תעבוד לשני הכיוונים) | הוספה או הסרה של חסימה שלי |
| `reports` | אין (מנהל בלבד) | הוספה בשמי בלבד |
| `data/users/...` | **חסום לגמרי** | חסום |
| `__lease`, `chatReadsDebug` | חסום (לא נחוץ אחרי המעבר לפונקציות שרת) | חסום |

**פונקציות שרת.** כולן בודקות זהות, חסימה, מסלול ומכסה:
- `hdm_send_interest`
- `hdm_open_chat`: נפתחת רק ב-🎯 הדדי, לפי המסלול והמכסה.
- `hdm_send_message`
- `hdm_list_profiles` / `hdm_get_profile`: שדות ציבוריים בלבד.
- `hdm_compatibility`: לבסיסי רק התווית, לפלוס ול-VIP גם ההסבר.
- `hdm_who_liked_me`: פלוס ו-VIP בלבד.
- `hdm_extended_analysis`: פלוס אחרי הדדיות, VIP אחרי 🎯.
- `hdm_delete_my_account`: אותה התנהגות כמו היום.

**פרטיות.** שום נתון לא משתנה ולא נמחק. רק מי שרואה אותו משתנה.
- **ציבורי (מוצע):** שם נוכחי, גיל, עיר, עיסוק, מגדר, מחפש/ת, תחומי עניין, ביו, תמונה, מספר דרך החיים, גובה, מצב משפחתי, ילדים, עישון.
- **פרטי, רק לבעלים:** תאריך לידה, שם פרטי ושם משפחה מלידה, אימייל, שאר המספרים הנומרולוגיים, רשימת `likes`, טווח הגילאים הרצוי.
- **חישוב ההתאמה** יעבור לשרת, מתוך השדות הפרטיים. לפני ההחלפה נשווה אותו לחישוב הקיים בדפדפן על כל זוגות הפרופילים, וההחלפה תתבצע רק אם אין אף הבדל.

## 6. סביבת Staging

**מה בדקתי:**
- בתוכנית החינמית מותרים [2 פרויקטים פעילים](https://supabase.com/pricing). פרויקט שני לבדיקות אפשרי בלי עלות.
- פרויקט חינמי [מושהה אחרי שבוע בלי פעילות](https://supabase.com/pricing), ומפעילים אותו מחדש בלחיצה.
- [Branching של Supabase](https://supabase.com/docs/guides/deployment/branching) זמין רק בתוכנית בתשלום.
- בתוכנית החינמית אין גיבויים אוטומטיים, ולכן הגיבוי הידני (`02_backup_snapshot.sql`) חשוב.

**שום מידע אישי לא מועתק:**
- ב-Staging יש רק מבנה (`supabase/staging/01_staging_schema.sql`) ו-12 פרופילים מומצאים (`02_staging_seed.sql`).
- את חשבונות הבדיקה יוצרים בהרשמה דרך האפליקציה, עם כתובות כמו `you+free@gmail.com`, `you+basic@gmail.com`. Gmail מעביר אותן לתיבה הרגילה.
- **הגנות בקבצים:** קובץ המבנה נעצר אם הוא מזהה טבלה עם נתונים (כלומר הפרויקט האמיתי), וקובץ הנתונים נעצר אם אין סימון Staging. שתי ההגנות נבדקו.

**גרסת האפליקציה ל-Staging:**
- ענף נפרד `staging` שלא ממוזג לעולם. ההבדל היחיד בו הוא כתובת הפרויקט והמפתח הציבורי של ה-Staging.
- מגישים אותו מכתובת נפרדת: מאגר GitHub נוסף עם GitHub Pages, או שירות שמגיש קבצים ישירות מענף.
- באתר האמיתי לא משתנה כלום.

**הגדרות Auth ב-Staging:**
- Site URL וכתובות ההפניה לאיפוס סיסמה יכוונו לכתובת ה-Staging.
- אישור אימייל: כמו בפרויקט האמיתי (ייקבע לפי שלב 0).

## 7. בדיקות

**ניסיונות תקיפה.** כל ניסיון צריך להיכשל בשרת:
- קריאת פרופיל של אחר עם תאריך לידה או שמות לידה.
- קריאת שיחה של אחרים, 🎯 של אחרים, דיווחים, או רשומות סיסמה.
- כתיבה בשם פרופיל אחר: 🎯, הודעה, עריכת פרופיל, חסימה.
- שינוי מסלול, מכסה או תאריכי מנוי.
- שיחה שישית במסלול בסיסי, כולל מקבילית ודרך ה-API.
- פתיחת צ׳אט בלי 🎯 הדדי, או מול משתמש חסום.
- שליחת הודעה עם מנוי שפג.

**ארבעת המסלולים:**
- **חינם:** צפייה בלבד.
- **בסיסי:** תווית התאמה ומכסת 5 שיחות.
- **פלוס:** "מי סימן אותי", וניתוח אחרי הדדיות.
- **VIP:** ניתוח אחרי 🎯, צ׳אט בהדדיות בלבד, הנחה.

**רגרסיה:**
- הרשמה (כולל הגבלת גיל ותמונה חובה), התחברות, יציאה, איפוס סיסמה.
- עריכת פרופיל, החלקה בין כרטיסים, 🎯, צ׳אט בזמן אמת, ✓✓ ומונה הודעות שלא נקראו.
- חסימה, דיווח, מחיקת חשבון, ומסך הבית באייפון.

**איך בודקים:**
- **אוטומטית:** מסד מקומי עם JWT אמיתיים לכל משתמש, ודפדפן אוטומטי.
- **ידנית:** מהאייפון ב-Staging, לפי רשימת בדיקה.
