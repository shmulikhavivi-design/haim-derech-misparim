# מנויים מתחדשים — מה מוכן ומה תלוי ב-Grow

**מצב נוכחי:** הכול מוכן ונבדק ב-Staging בלבד. אין חיבור ל-Grow, אין חיובים, ואין שינוי ב-Production או ב-`index.html`.
עד לאישור Grow לשירות Token + חיובים חוזרים, אין להפעיל שדרוגים בתשלום או מנויים מתחדשים ב-Production.

## המודל שאושר (17.10.2026)
- **כרטיס שמור (Token)** — Grow "Premium recurring – manage by you": בהצטרפות נשמר Token, והשרת שלנו מבצע כל חיוב
  (`createTransactionWithToken`), בלי שהלקוח מזין שוב פרטי אשראי.
- חיוב ראשון ביום ההצטרפות; חידוש אוטומטי כל חודש באותו תאריך (שעון ישראל), עד ביטול.
- **שדרוג בכל שלב:** חיוב יחסי רק על יתרת התקופה = (מחיר חדש − מחיר נוכחי) × (זמן שנותר ÷ אורך התקופה), מעוגל לאגורה.
  המסלול החדש מופעל מיד אחרי אישור התשלום; תאריך החיוב החודשי לא משתנה; מהחידוש הבא — מחיר המסלול החדש.
  דוגמה: בסיסי→פלוס באמצע החודש = ₪9.50.
- ביטול עוצר את החידוש הבא; הגישה נשארת עד סוף התקופה ששולמה.
- חיוב שנכשל: המנוי לא מוארך. עד 3 ניסיונות, לפחות 48 שעות ביניהם; אחר כך החידוש נעצר.

## Grow — מה בדקנו בתיעוד הפומבי
| נושא | מה מצאנו |
|---|---|
| חיוב יחסי (proration) | **אין** תמיכה מובנית. השרת שלנו מחשב את הסכום ומחייב אותו כחיוב חד-פעמי בכרטיס השמור. |
| שמירת תאריך החידוש | במודל Token השרת שלנו קובע את מועד כל חיוב, ולכן התאריך נשמר. בהוראת קבע רגילה יש רק `chargeDay` (יום בחודש) ב-`updateDirectDebit`. |
| Token וחיובים חוזרים | `createPaymentProcess` (שמירת Token) + `createTransactionWithToken` (`isRecurringDebitPayment=1`, ואז `recurringDebitId`). **דורש הרשאה מיוחדת מ-Grow** ("Premium recurring"). |
| אימות התראות שרת | לא מתועד בפומבי (יש "Approve Transaction" ו-Server-to-Server Callback). צריך הנחיה מ-Grow. |
| החזרים | `Refund Transaction`. |

כרגע Grow אישרה **סליקה רגילה בלבד**.

## תלוי באישור Grow
1. אישור שירות Token + Premium recurring ("manage by you"), ומפתחות לסביבת בדיקות (sandbox).
2. הנחיה לאימות התראות שרת (Server-to-Server / Approve Transaction).
3. אישור שמותר לחייב חיוב חד-פעמי בסכום משתנה בכרטיס השמור (לשדרוג), ומה הסכום המינימלי לחיוב.
4. Edge Functions: `grow-checkout` (דף תשלום + שמירת Token), `grow-webhook` (אימות → `hdm_billing_apply_grow_event`),
   `grow-charge` (משימה מתוזמנת: `hdm_billing_claim_due_renewals` → חיוב בכרטיס השמור; שדרוג → חיוב יחסי).
5. בדיקות מקצה לקצה בכרטיסי בדיקה, ורק אז `HDM_BILLING_LIVE = true` ב-Staging.
6. Production — רק באישור מפורש.

## דורש אישור/החלטה
- **סעיף המנויים בתנאי השימוש:** טיוטה ב-`staging.html`. לפני העלייה — בדיקה משפטית, ופרסום גרסת תנאים חדשה עם אישור מחדש מכל המשתמשים (`hdm_admin_publish_terms`).
- **מע"מ:** לוודא שהמחירים המוצגים כוללים מע"מ (אם חל).
- **יתרה קטנה מ-₪1 בשדרוג:** כרגע השדרוג מופעל בלי חיוב (לטובת הלקוח). אפשר לשנות.
- **שנמוך באמצע חודש:** לא זמין (ביטול והצטרפות מחדש בסוף התקופה).
