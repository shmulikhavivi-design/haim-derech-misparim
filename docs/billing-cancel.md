# ביטול מנוי — מה מוכן ומה תלוי ב-Grow

**מצב:** מוכן ונבדק ב-Staging בלבד (18.10.2026). אין חיבור ל-Grow, אין חיובים, לא נשלחים מיילים, ואין שינוי ב-Production או ב-`index.html`.
נבנה מעל PR #28 (מנויים מתחדשים).

## מה הלקוח רואה
- **ניהול מנוי** (במסך הראשי ובהגדרות) ← **ביטול מנוי**. בהגדרות יש גם קיצור "ביטול מנוי" ומסמך "מדיניות ביטול מנוי".
- בקשת אישור: מועד סיום המנוי, "לא יתבצעו חיובים נוספים", "ביטול המנוי לא מוחק את החשבון או את הפרופיל".
  **ביטול חידוש רגיל**: החידוש נעצר, המנוי פעיל עד סוף התקופה ששולמה ומסתיים בלי חיוב נוסף, בלי החזר יחסי (אלא אם הדין מחייב).
  **ביטול עסקה לפי חוק הגנת הצרכן** (נפרד, בתוך 14 ימים מההצטרפות מתוך האפליקציה; אחר כך — אימייל/טלפון): השירות מופסק עם הביטול, ההחזר נפתח לטיפול ומחושב לפי החוק. (עודכן 19.10.2026, `23_staging_billing_statutory_cancel.sql`)
- אחרי האישור:
  - **"סטטוס: בקשת הביטול בטיפול"** — כשיש סדרת חיובים ב-Grow, עד שמתקבל אישור מ-Grow. החיובים חסומים כבר מרגע הבקשה.
  - אם האישור מתעכב (3 כשלים) — הודעה שמטפלים בזה, ועדיין לא יתבצע חיוב.
  - **"סטטוס: המנוי בוטל"** — רק אחרי אישור מ-Grow (או מיד, כשאין שום סדרה ב-Grow לבטל).
  - בכל מצב: תאריך סיום המנוי, ושבסופו החשבון עובר לחינם והפרופיל נשמר.
- מסך הפתיחה (לא מחובר): קישור "ביטול מנוי" ו"מדיניות ביטול מנוי".

## בשרת (`21_staging_billing_cancel.sql`)
| רכיב | מה הוא עושה |
|---|---|
| `hdm_billing_cancel(p_refund)` | עוצר את החידוש מיד, רושם בקשת ביטול (מועד, תאריך סיום, בקשת החזר), מכניס מייל לתור. תואם לאחור. |
| `hdm_cancel_requests` | תיעוד כל בקשה: `pending` עד אישור Grow, `confirmed` אחריו. |
| `hdm_billing_outbox_done` | תשובת Grow: הצלחה ← `confirmed` + מייל "הביטול אושר"; כשל ← נרשם; אחרי 3 ← לטיפול ידני. |
| `hdm_billing_cancel_issues()` | רשימה למנהל: ממתינים, תקלות, בקשות החזר פתוחות. |
| `hdm_email_outbox` | מיילי "הבקשה התקבלה" / "הביטול אושר", אחד מכל סוג לכל בקשה. הכתובת נלקחת מהחשבון בזמן השליחה. |
| `hdm_billing_status()` | מוסיף `cancel` (מצב, מועדים, עיכוב, החזר), `refundEligible`, `refundUntil`. |

## תלוי ב-Grow
1. API לביטול סדרת החיובים (`recurringDebitId` / `directDebitId`) ותשובה מאומתת — ב-`supabase/functions/hdm-billing-worker` (טיוטה, `GROW_LIVE` כבוי).
2. ביצוע החזר כספי (`Refund Transaction`) לבקשות ביטול עסקה לפי החוק (החזר בניכוי התקופה שבה השירות ניתן). עד אז — טיפול ידני מתוך `hdm_billing_cancel_issues()`.
3. בדיקה מקצה לקצה בסביבת הבדיקות של Grow.

## לא תלוי ב-Grow, אבל עוד לא פעיל
- **שליחת המיילים בפועל:** הפונקציה `hdm-billing-worker` (טיוטה, לא פרוסה ולא הורצה) שולחת דרך ה-API של Brevo.
  דרוש מפתח API של Brevo כסוד של הפונקציה, ופריסה + משימה מתוזמנת ב-Staging.
- **נוסח המדיניות:** טיוטה לבדיקה משפטית. לפני פרסום — אישור עורך דין, ואז גרסת תנאים חדשה עם אישור מחדש מכל המשתמשים.
- Production — רק באישור מפורש.
