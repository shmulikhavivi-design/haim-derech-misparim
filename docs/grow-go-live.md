## מ-Grow צריך לקבל
1. אישור לשירות **חיוב חוזר / כרטיס שמור (טוקן)** — עד היום אושרה סליקה רגילה בלבד.
2. פרטי API לסביבת הבדיקות: יצירת דף תשלום, חיוב בטוקן, **ביטול סדרת חיובים**, **החזר כספי**, ו-webhook לאישור תשלום (כולל דרך לאמת שהוא אמיתי).
3. סביבת בדיקות (sandbox) לבדיקה מקצה לקצה.

## מה נעשה אחרי שיש אותם (כל שלב באישור מפורש)
1. השלמת `supabase/functions/hdm-billing-worker` מול ה-API של Grow (`GROW_LIVE` כבוי עד הבדיקות), ומפתחות כסודות בלבד.
2. בדיקה מקצה לקצה ב-Staging מול ה-sandbox של Grow: רכישה, חידוש, שדרוג, ביטול, החזר, חיוב שנכשל.
3. מפתח API של Brevo לשליחת מיילי האישור (סוד של הפונקציה).
4. גיבוי מלא של Production, ואז העברת SQL 17/19/21/23 ל-Production — **רק באישור מפורש**.
5. הסרת המשפט "כרגע המסלולים בתשלום עדיין לא פתוחים לרכישה" מהמסמכים, `HDM_BILLING_LIVE = true`, בניית `index.html` ומיזוג — **רק באישור מפורש**.
6. גרסת תנאים חדשה ואישור מחדש מכל המשתמשים (מנגנון ההסכמה הקיים), אחרי בדיקה משפטית.
