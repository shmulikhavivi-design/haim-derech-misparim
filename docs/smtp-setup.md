# שליחת מיילים מקצועית (SMTP) ל-Supabase — מדריך לאייפון

**למה זה חוסם השקה:** בלי SMTP משלכם, Supabase שולח רק מספר קטן מאוד של מיילים, ורק לחברי הצוות של הפרויקט. משתמשים אמיתיים לא יקבלו מייל אישור הרשמה ולא מייל "שכחתי סיסמה". אחרי המעבר, "שכחתי סיסמה" הוא הדרך היחידה של חשבונות קיימים להתחבר לפרופיל שלהם.

**שני מסלולים:**
- **להשקה עכשיו (חינם, בלי דומיין): Gmail SMTP** — סעיף א׳.
- **שדרוג בהמשך (כשיהיה דומיין): Resend** — סעיף ב׳.

**למה Gmail SMTP כן עובד, ושירותים אחרים לא:** כשהמייל נשלח דרך השרת של Gmail עצמו מחשבון ה-Gmail, Google חותמת עליו, והוא עובר את בדיקות האמינות (SPF/DKIM/DMARC). לעומת זאת, שירות חיצוני (Brevo, SendGrid וכו') לא יכול לשלוח בשם `@gmail.com` — Gmail ו-Yahoo דורשים שהשולח יהיה בעל הדומיין.

# א׳. Gmail SMTP — פתרון ההשקה (חינם)

**המגבלות (חשוב לדעת):**
- עד **500 מיילים ביממה** (חלון מתגלגל של 24 שעות). חריגה עוצרת את השליחה לעד 24 שעות.
- Google עלולה לחסום התחברות "חשודה" משרתי Supabase. לכן חובה לבדוק מיד אחרי ההגדרה (שלב א4).
- שינוי הסיסמה של חשבון ה-Gmail מבטל את סיסמת האפליקציה — צריך ליצור חדשה ולעדכן ב-Supabase.
- השולח יופיע כ-`life.through.numbers333@gmail.com`. זה תקין ואמין, פחות "מקצועי" מדומיין.
- Google ממליצה על שירות ייעודי לשליחה אוטומטית בהיקף גדול. להשקה ולמאות משתמשים ראשונים זה מספיק.

### א1. סיסמת אפליקציה בחשבון Google
בחשבון `life.through.numbers333@gmail.com`:
1. myaccount.google.com ← **Security** ← להפעיל **2-Step Verification** (אם עוד לא פעיל).
2. myaccount.google.com/apppasswords ← שם: `Supabase` ← **Create**.
3. מתקבל קוד של 16 תווים. **מעתיקים אותו ישר ל-Supabase (שלב א2)** — לא לצ'אט ולא ל-GitHub. Google מציגה אותו פעם אחת.

### א2. הגדרה ב-Supabase (Production)
Supabase ← **Haim Derech Misparim** ← Authentication ← Emails ← **SMTP Settings** ← Enable Custom SMTP:

| שדה | ערך |
|---|---|
| Sender email | `life.through.numbers333@gmail.com` |
| Sender name | `חיים דרך מספרים` |
| Host | `smtp.gmail.com` |
| Port | `465` |
| Username | `life.through.numbers333@gmail.com` |
| Password | סיסמת האפליקציה משלב א1 (בלי רווחים) |

לוחצים **Save**. אם נשארו שם הגדרות Gmail חלקיות מפעם קודמת — פשוט מחליפים אותן בערכים האלה.

### א3. מגבלת קצב
Authentication ← **Rate Limits** ← מגבלת המיילים לשעה: **30**. זה מספיק להשקה ושומר מרחק בטוח ממגבלת Gmail.

### א4. בדיקה (חובה, לפני Confirm email)
- באתר הפעיל: "שכחתי סיסמה" עם כתובת מייל של אחד מכם.
- המייל צריך להגיע תוך דקה ולא לספאם.
- אם לא הגיע: Supabase ← Logs ← **Auth** — מחפשים שגיאת SMTP. השגיאה הנפוצה היא סיסמת אפליקציה שגויה (שלב א1).
- בתיבה הנשלחים (Sent) של חשבון ה-Gmail יופיע עותק של כל מייל שנשלח.

### א5. רק אחרי שהבדיקה עברה
Authentication ← Sign In / Providers ← Email ← להדליק **Confirm email**.

# ב׳. שדרוג בהמשך: דומיין + Resend

## ההמלצה לשלב הבא: דומיין קטן + Resend
- **דומיין:** כ-10–12 דולר לשנה (כדאי לוודא מחיר בזמן הקנייה). לדוגמה `haimmisparim.com` או כל שם פנוי אחר.
- **Resend:** שירות שליחת מיילים עם מדריך רשמי ל-Supabase. המסלול החינמי מספיק להשקה: עד 3,000 מיילים בחודש ועד 100 ביום.
- **כתובת השולח:** `noreply@<הדומיין>`, בשם `חיים דרך מספרים`.
- **כתובת הקשר** בתוך המיילים נשארת `life.through.numbers333@gmail.com`. היא רק מופיעה בטקסט, לא שולחת.

## השלבים (כ-20 דקות, הכול מהאייפון)

### 0. מעבר מ-Gmail
ב-SMTP Settings מחליפים את פרטי Gmail בפרטי Resend (שלב 4). אין צורך לכבות קודם.

### 1. קניית דומיין
- באתר רשם דומיינים (למשל Cloudflare Registrar, שמוכר במחיר עלות ומנהל גם את ה-DNS באותו מקום).
- **לא צריך** אתר או תיבת מייל על הדומיין. הוא משמש רק לאימות השולח.

### 2. חשבון Resend ואימות הדומיין
1. נרשמים ב-resend.com.
2. **Domains ← Add Domain** ← מקלידים את הדומיין.
3. Resend מציג כמה רשומות DNS (TXT / MX). אם מוצעת הגדרה אוטומטית מול הרשם — משתמשים בה. אחרת מעתיקים כל רשומה ל-DNS של הדומיין אצל הרשם.
4. חוזרים ל-Resend ולוחצים **Verify**. האימות לוקח בדרך כלל כמה דקות.

### 3. מפתח SMTP
- Resend ← **API Keys ← Create API Key**, הרשאה **Sending access** בלבד.
- **המפתח הוא סיסמת ה-SMTP.** מעתיקים אותו ישר לשדה ב-Supabase (שלב 4). **לא שולחים אותו בצ'אט** ולא שומרים אותו ב-GitHub.

> **על החיבור האוטומטי Resend ↔ Supabase (Integrations):** הוא חוסך הקלדה, אבל מבקש גישה לארגון ב-Supabase. אם מסך ההרשאה מבקש גישת כתיבה לכל הארגון (כולל Production), כמו בפעם הקודמת — מוותרים עליו וממשיכים ידנית בשלב 4.

### 4. הגדרה ב-Supabase (Production)
Authentication ← Emails ← **SMTP Settings** ← Enable Custom SMTP:

| שדה | ערך |
|---|---|
| Sender email | `noreply@<הדומיין>` |
| Sender name | `חיים דרך מספרים` |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | המפתח משלב 3 |

לוחצים **Save**.

אחר כך: Authentication ← **Rate Limits** ← מגבלת המיילים לשעה. מעלים אותה ל-100 לפחות.

### 5. בדיקה
- באתר הפעיל (עדיין הגרסה הנוכחית): "שכחתי סיסמה" עם המייל שלכם.
- המייל צריך להגיע תוך דקה, מהשולח `noreply@<הדומיין>`, ולא לספאם.
- ב-Resend ← **Emails** רואים את המייל ואת הסטטוס שלו (Delivered).

### 6. Staging (לא חובה)
אותה הגדרה גם בפרויקט **Haim Derech Misparim Staging**, עם מפתח API נפרד. אפשר להשתמש באותו דומיין.

## רק אחרי שהבדיקה בשלב 5 עברה
Authentication ← Sign In / Providers ← Email ← להדליק **Confirm email**.
**הסדר חשוב:** אם מדליקים את Confirm email לפני שה-SMTP עובד, משתמשים חדשים לא יוכלו לסיים הרשמה.

## חלופות חיצוניות בלי דומיין (לא מתאימות)
Brevo מאפשר שליחה בלי דומיין, אבל מחליף את כתובת השולח בכתובת של Brevo עצמה. המיילים נראים פחות אמינים ונוטים להגיע לספאם, ו-Brevo מגדירים את זה כפתרון זמני. מתאים לכל היותר לבדיקות.
